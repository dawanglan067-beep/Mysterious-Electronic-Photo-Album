# 电子相册基础修图功能规划书

> 已整合至 [图片编辑与多图合成总计划书](photo-editing-master-plan.md)。开发顺序、阶段状态和跨模块规则以总计划为准；本文件保留专项详细要求。

版本：1.5

编写日期：2026 年 10 月 20 日  
更新日期：2026 年 10 月 27 日

项目技术：C++17、Qt 6.8.3、CMake  
文档用途：确定第一版基础图片编辑的功能范围、代码职责、开发顺序与验收要求。

## 一 建设目标

在现有电子相册基础上建立操作可撤销、原图不受损、结果可正确导出的基础修图流程：

**选择照片 → 调整构图与颜色 → 对比原图 → 撤销或重做 → 导出副本。**

本规划面向静态图片。第一版以基础编辑的完整性和可靠性为完成目标，不以复刻 Photoshop 全部功能为目标。

## 二 现有基础与当前进度

现有项目具备照片墙、单图浏览、缩放平移、旋转镜像、直方图，以及亮度、对比度、饱和度和多种滤镜。图像计算已拆分到 ImageProcessor，直方图由 HistogramWidget 负责。

PhotoEditDocument 已统一保存原图路径、原始图像、亮度/对比度/饱和度/滤镜参数，以及旋转和镜像状态。PicShow 已删除这些数据的重复成员；加载、预览、重置、清空和切图流程均读取或更新文档。预览与完整尺寸渲染现已共用 PhotoEditDocument::Render()，拖动滑块时通过预览尺寸参数保留降采样处理。

撤销重做核心功能已使用 QUndoStack/QUndoCommand 实现，覆盖调色、滤镜、旋转、镜像和“还原参数”。一次滑块拖动记为一步，切图、清空或加载失败时清除历史；支持界面按钮及 Ctrl+Z、Ctrl+Y、Ctrl+Shift+Z。历史只保存编辑状态，不复制整张原图。

最近一轮常规比例和 QT_SCALE_FACTOR=2 的离屏自动回归均为 Failures: 0，覆盖参数与实际预览同步、重置、切图、加载失败、滑块拖动合并、撤销重做、分支编辑、快捷键、修改状态和裁剪。裁剪包含旋转镜像组合、重复裁剪、八个控制点、固定比例、边界、缩放平移、确认取消及源文件保护；已检查裁剪窗口截图。离屏事件验证不等同于多显示器、真实鼠标交互或安全导出验收。

删除使用照片墙“删除所选（回收站）”或树中照片右键菜单，移动相册内实际文件，成功后同步列表、收藏、缩略图及导航，重开不再出现。外部素材只删除相册副本；取消或回收失败保留文件、条目及编辑。当前编辑图可先导出副本、继续删除或取消；该保护仅覆盖删除，通用离开提醒仍待阶段五。常规及 200% 离屏回归通过，确认窗口截图已检查，系统回收站恢复及真实鼠标交互待手工验收。文件恢复使用系统回收站，不加入编辑撤销栈。

目录管理：磁盘确实为空的“素材”目录默认隐藏，检查包含隐藏及非图片文件，保留磁盘目录。子目录右键可“隐藏文件夹（本次运行）”或“删除文件夹（移到回收站）…”，相册根右键可恢复显示隐藏目录及空素材目录，无需关闭父相册。隐藏不清空编辑；整目录回收包含其中所有文件，须明确确认，并保护目录内当前编辑图，导出副本不得写回待删除目录。失败保留子树与编辑；成功才同步列表、收藏和导航，重开目录不再出现。再次登记素材会重建或恢复显示目录。通用离开保护仍待阶段五。

第一版默认导出副本或另存素材，两者禁止覆盖源图；只有独立的覆盖原图操作经确认、备份和安全提交才允许替换。当前代码尚未提供该覆盖入口。对其他已有输出文件，明确确认后才允许替换。

本版不包含视频剪辑、复杂抠图、人像精修、图层合成、RAW、HDR、完整印刷色彩管理和 AI 生成式处理。后续需要这些能力时另行规划，不把它们混入当前验收范围。

## 四 模块职责

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| PhotoEditDocument | 保存原图、参数、几何编辑状态和修改状态 | 不直接操作界面控件 |
| PicShow | 展示图片，接收控件操作，协调编辑流程 | 不再重复保存调色参数 |
| ImageProcessor | 根据输入图像和参数执行计算 | 不读取滑块或弹出窗口 |
| QUndoStack 与编辑命令 | 保存前后状态，执行撤销重做 | 不为每次滑动复制整张图片 |
| CropTool | 裁剪框交互、比例约束、坐标转换、确认取消 | 预览期间不永久改写原图 |
| ImageExportService | 全尺寸渲染、编码、安全写入 | 不把屏幕预览当成导出原图 |

编辑数据的唯一来源是 PhotoEditDocument。PicShow 的滑块和数值标签只是状态的显示与输入入口。

### 参数读写约定

文档通过 parameters() 返回参数副本，通过 setParameters() 接收整套参数。界面先读取副本，修改对应数值，再统一交回文档。文档负责限制亮度、对比度和饱和度的有效范围。

迁移结束后删除 PicShow 的重复参数成员。原来的 setBrightness() 可以保留为便捷接口，但应修改同一份参数，不能再建立第二份亮度状态。

### 渲染顺序约定

迁移已有功能时保留当前旋转、镜像、降采样预览与算法顺序，先验证结果一致。加入裁剪前，再明确裁剪坐标所属空间和完整处理顺序，并由预览与导出共用该定义。

不能直接以全尺寸 Render() 替换所有预览代码，否则可能丢失现有滑块拖动时的降采样优化。滤镜与几何操作顺序也不能随迁移悄悄改变。

## 五 开发步骤与完成条件

### 阶段一 统一编辑状态

1. 为 PhotoEditDocument 添加 parameters() 和 setParameters()。
2. 让亮度、对比度、饱和度及滤镜统一写入文档。
3. 让渲染读取文档参数，保留现有输出与交互行为。
4. 同步改造加载、重置、清空、加载失败和图片切换逻辑。
5. 删除旧参数，检查所有引用和初始化代码。

完成条件：四类参数调节正常；控件与文档一致；切换照片不继承上一张效果；加载失败不会残留旧图；清空后不再渲染旧文档。

### 阶段二 撤销与重做

使用 QUndoStack 和 QUndoCommand 记录编辑前后状态。一次滑块拖动合并为一次历史操作，键盘或鼠标步进也应形成合理操作单位。恢复控件时阻止信号递归生成新命令。

旋转、镜像与恢复默认状态一并纳入历史。每张照片使用独立历史，或切换时明确清空当前历史，避免撤销到另一张照片。

完成条件：连续调整后可以逐步撤销重做；分支编辑正确清除失效的重做记录；界面、文档和预览始终一致。修改状态应反映当前是否存在未处理的编辑，不能只用历史索引判断导出状态。

### 阶段三 裁剪

支持移动裁剪框、八个控制点、比例锁定和结果尺寸显示。进入工具时建立临时状态；确认后生成历史命令；取消时恢复进入工具前的状态。

建立屏幕坐标、画布坐标与图像坐标的转换。处理缩放、平移、高 DPI、旋转镜像及图像边界，裁剪宽高不得为零。固定比例在边界附近也必须保持有效。

完成条件：不同显示缩放下选取同一区域，导出像素区域一致；旋转镜像后裁剪方向正确；裁剪可撤销；取消不产生实际编辑。

### 阶段四 原图对比与导出

原图对比只切换显示，不修改文档和历史；明确原图与编辑后图像的显示适配方式。

导出从原始图像和当前编辑状态重新生成全尺寸 QImage。使用 QImageWriter 编码到 QSaveFile，成功后提交，失败则保留原目标文件。JPEG 遇到透明像素时使用明确背景色。根据运行时支持情况启用编码格式。

当前实现：ImageExportService 统一处理完整尺寸渲染、编码及安全写入，禁止覆盖源照片（包含路径规范化、Windows 大小写及可解析的符号链接别名），关闭直接写入回退。界面提供运行时支持的 PNG/JPEG/BMP 格式，默认导出 PNG 副本；未填扩展名时按所选格式补齐，有扩展名时按实际扩展名编码，不支持的扩展名报错。JPEG 可选择 0–100 质量，界面明确使用白色背景；PNG 保留透明度。导出不改变编辑历史或加载基准。已通过全尺寸像素、透明度、JPEG 背景、成功替换、失败保护及源文件保护自动检查；真实保存窗口的选择、取消和覆盖确认仍需手工验收。

完成条件：输出方向、尺寸、透明度和效果正确；拖动预览不会导致低分辨率导出；失败或取消不损坏原图和已有输出。

阶段四新增需求已合入[总计划 A4a/A4b](photo-editing-master-plan.md)：先完成裁剪结果另存与相册登记，再实现独立覆盖保存。另存使用当前完整尺寸可见效果，保留原始编辑源与历史；覆盖成功后验证实际输出，再建立新源图、默认参数和修改基准并清空旧历史，旧照片从备份恢复。禁止直接用先清历史、失败会清文档的切图流程完成覆盖重载。保存与重载结果须区分，缩略图缓存及旧异步任务须同时失效。详细模块改动和验收见总计划及[可行性报告](crop-save-feasibility-report.md)。

### 阶段五 完整流程与离开提醒

编辑后切换图片或关闭页面时提供导出副本、放弃修改、取消离开。导出失败或用户取消保存窗口时继续停留，不丢弃编辑。

第一版未保存草稿时应说明：导出结果是成品图片，不能代替可恢复参数的编辑工程。若后续允许导出尺寸、质量变化，应区分原尺寸成品导出与分享缩略图，避免误清除修改提示。

完成条件：用户可以完整完成打开、编辑、对比、撤销重做、导出和离开流程，且已有相册功能正常。

## 六 图像与文件处理要求

原始图像不反复覆盖，避免累积压缩和失真。第一版沿用现有 8 位图像处理能力，不宣称已支持 16 位、RAW 或专业印刷色彩。

加载时明确处理 EXIF 方向；预览和导出保持一致，避免重复旋转。元数据保留能力必须单独验证，不默认承诺完整保存 EXIF。优先建立明确的 sRGB 输出策略，后续再扩展色彩管理。

预览可以缩小图像，最终导出必须重新计算。后续引入后台预览时，后台只处理 QImage 与数据，GUI 线程负责 QWidget 和 QPixmap；过期任务结果不能覆盖新参数或另一张照片。

## 八 当前执行安排

阶段二修改状态判断已实现并通过自动回归：文档保存加载基准，编辑和历史恢复后直接比较 EditState；撤销回基准即使历史非空也未修改，单独还原调色不会清除几何修改。切图、清空、加载失败会重置基准。安全导出不更新此内容基准，导出成功状态记录与离开提醒将在阶段五接入。

当前已进入阶段三，裁剪实现约定如下：

1. CropDialog/CropCanvas 保存临时选区，拖动选区移动，八个控制点调整，支持自由比例、原图比例、1:1、4:3、3:2、16:9，显示结果像素尺寸。
2. 滚轮缩放、右键拖动画布，选区保持图像像素坐标。Enter 应用，Esc 或取消退出；确认产生一步历史，取消不改变文档、历史和修改状态。
3. 文档 crop 字段保存原图上的整数像素矩形，空值表示完整原图；处理顺序统一为原图裁剪 → 镜像 → 90 度倍数旋转 → 降采样预览（如启用）→ 调色/滤镜。无裁剪时保持旧处理顺序。
4. 工具显示当前已裁剪、镜像和旋转后的完整尺寸结果；确认时将所选区域反向映射到原图坐标，因此重复裁剪、旋转后裁剪仍使用同一份原图。
5. 常见固定比例采用整数倍像素尺寸。原图比例若为较大的互质整数，允许不超过一个像素的比例取整误差，避免无法缩小选区。图片太小而无法容纳固定比例整数尺寸时，禁止应用空选区。
6. 本阶段检查裁剪像素、透明度、旋转镜像组合、重复裁剪、八个控制点、边界比例、缩放平移及历史恢复；另需在实际显示器上检查高 DPI 和拖动体验。阶段三验收后再进入原图对比和安全导出。

注意：“还原参数”仍仅还原调色与滤镜。“恢复全部原图”已提供独立按钮，清除裁剪、旋转、镜像、调色与滤镜，通过一条历史记录支持撤销重做；恢复加载基准后取消已修改标记，重复恢复不新增空记录。保留当前视图缩放和平移，不重新读取或写入源文件。导出成功基准和离开提醒仍需后续实现。

学习与开发按照“解释职责和语法 → 手动输入小段代码 → 编译 → 检查运行结果 → 再迁移下一处”的方式推进。未经明确要求，不由辅助工具直接替开发者修改程序文件。
