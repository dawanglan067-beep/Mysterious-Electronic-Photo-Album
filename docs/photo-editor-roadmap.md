# 电子相册专业图片编辑开发规划

编写日期：2026-10-16。范围：静态图片编辑；不包含视频时间线、音轨剪辑。
本文件为开发方案，不代表下面的功能已经实现。

## 一、官方产品调研

| 产品 | 官方资料中的主要能力 | 本项目值得借鉴的方向 |
| --- | --- | --- |
| Adobe Photoshop | 图层、调整图层、蒙版、选区；裁剪、拉直、透视；色阶、曲线；修复、移除对象、文字与绘画 | 可撤销编辑、准确裁剪、局部调整、图层合成 |
| Adobe Lightroom | 照片调色、曝光、高光阴影、曲线、预设；画笔及主体等蒙版；局部调整 | 面向照片的参数式编辑和预设工作流 |
| GIMP 3 | 图层、通道、路径、文字；可重新调整和开关的非破坏性图层效果；色彩空间管理 | 将编辑参数与原始像素分离，保留后续修改能力 |
| darktable | 全流程非破坏性编辑、RAW、浮点图像处理、ICC 色彩管理、GPU 加速 | 原图保护、明确的色彩空间和高质量导出 |

上述内容来自文末官方资料，功能名称和可用条件以各产品页面为准。

## 二、项目现状

已有：照片墙、单图浏览、缩放平移、90 度旋转、镜像、直方图；亮度/对比度/饱和度；灰度、怀旧、反色、高斯模糊、锐化、边缘、浮雕；处理后图片导出、相册 PDF 导出。

当前 ImageProcessor 主要采用 8 位 ARGB32 运算，尚不能宣称具有 RAW、16 位/HDR 或完整专业色彩管理能力。
当前导出通过 QPixmap 保存；专业导出需要逐步改为从全分辨率编辑文档渲染 QImage。

优先补齐：裁剪、任意角度拉直、撤销重做、编辑草稿、原图对比、安全导出、曝光与白平衡。

## 三、第一阶段：可靠的编辑基础（P0）

### 编辑文档与无损处理

- 新增 PhotoEditDocument：保存源路径、源图像、操作序列、编辑参数、当前工具与修改状态。
- 编辑中不反复覆盖源像素；从源图和操作序列重新渲染，避免多次压缩和累积失真。
- 新增 EditHistory：采用 QUndoStack/QUndoCommand；一次拖动滑块形成一个历史操作。
- 切换图片、关闭编辑页时，存在修改则提供保存草稿、放弃、取消选项。
- 草稿保存到应用数据目录，含版本、源文件标识和参数；不在用户照片目录随意创建文件夹。
- 源图被外部替换时，检查路径、尺寸、修改时间；存在冲突时提示，不直接把旧草稿套到新图上。

### 裁剪、拉直、尺寸

- 自由裁剪；原图比例、1:1、4:3、3:2、16:9；横竖比例交换；像素尺寸输入。
- 支持拖动裁剪框与八个控制点，显示裁剪后尺寸；Enter 应用，Esc 取消本次预览。
- 任意角度旋转/拉直，提供自动内接裁剪以排除旋转产生的空白角。
- 工具坐标统一映射到原图/当前操作空间；缩放、高 DPI、平移时不能裁错区域。
- 分开定义画布尺寸、图片像素尺寸及显示缩放，不能将屏幕截图当成导出结果。

### 安全导出

- 默认导出副本；覆盖原图必须明确确认。
- JPEG：质量、尺寸、背景色；PNG：透明通道；WebP：根据运行时编码支持启用。
- 采用 QImageWriter 编码到 QSaveFile，成功后提交；错误或取消不得损坏已有目标文件。
- 正确处理 EXIF 方向，避免二次旋转；元数据是否保留必须明确说明，不能默认承诺完整保留。
- 导出图片颜色转换到明确的 sRGB 输出；无配置文件的图片采用显式且可解释的默认策略。

验收：连续编辑和撤销后结果正确；重新打开草稿恢复参数；不同缩放下裁剪区域一致；导出不改变原图；切换图片不会继承上一张未保存状态。

## 四、第二阶段：摄影调色（P1）

- 曝光 EV、色温/色调、高光、阴影、白场、黑场、自然饱和度。
- RGB 色阶与曲线；首先实现总通道，之后扩展分通道。
- 原图/效果按住对比与分屏对比；直方图随预览更新。
- 保存、应用、重置预设；预设带格式版本。
- 预览使用缩小图，全尺寸导出重算；后台任务带版本号，过期结果不能覆盖新参数。
- 曝光等计算明确工作空间；不能把亮度加法直接改名为曝光。白平衡起步定位为 JPEG/PNG 的调色近似，不声称是 RAW 白平衡。

验收：零参数不改变图像；纯灰与肤色测试图无意外色偏；快速拖动不会显示旧结果；全尺寸导出与预览方向、参数一致。

## 五、第三阶段：实用编辑与局部处理（P1/P2）

1. 文字、箭头、矩形、圆形、水印，支持位置、颜色、大小及透明度；高 DPI 导出位置一致。
2. 马赛克与区域模糊，适合相册分享隐私处理。
3. 矩形、椭圆与画笔蒙版；羽化、添加、减去、反选；局部曝光、饱和度和模糊。
4. 克隆图章和小范围修复：先做用户指定来源的克隆，再评估 OpenCV inpaint。复杂纹理和大面积修复不承诺完美。

标注和蒙版先以可编辑对象保存，导出时合成，不能每次移动文字都永久写入原图。
验收：撤销能完整恢复笔画、文字和蒙版；旋转/裁剪后对象坐标一致；取消笔画不会残留。

## 六、第四阶段：高级合成与扩展（P2/P3）

- 图层：图片、文字、调整图层；可见性、顺序、不透明度、基础混合模式及蒙版。
- 透视校正、批量套用预设、批量尺寸与水印；每张图片独立报告结果和冲突。
- RAW：评估 LibRaw 等解码组件；先确定解码授权、白平衡、去马赛克和色彩转换，不将解码库等同于完整 RAW 编辑器。
- 16 位/浮点处理：升级处理管线和导出策略后再宣传；高精度管线不应中途降回 ARGB32。
- AI 抠图、降噪、超分辨率、对象移除：单独评估模型、授权、硬件和耗时；如使用云服务，明确上传内容、费用及用户确认。

本阶段按需求推进，不作为第一版完成条件。

## 七、建议的代码组织

| 模块 | 职责 |
| --- | --- |
| PhotoEditDocument | 原图、编辑状态、操作顺序、修改状态 |
| EditHistory / EditCommand | 撤销重做、拖动操作合并 |
| PhotoCanvas | 显示、坐标映射、工具事件；从 PicShow 渐进迁移 |
| CropTool / AnnotationTool / MaskTool | 工具临时状态及确认取消 |
| ImageProcessor | 无界面的图像计算；保留现有算法作为兼容操作 |
| PreviewRenderer | 降采样预览、任务版本、取消与结果分发 |
| ImageExportService | 全尺寸渲染、编码、颜色转换、安全落盘 |
| EditProjectStore | 草稿版本、源图标识、读取恢复 |

PicShow 保留页面协调职责，不再把全部工具、算法和文件处理塞回其中。后台只处理 QImage 和数据；QWidget/QPixmap 的使用留在 GUI 线程。任务取消、关闭页面和对象销毁时统一管理生命周期。

操作顺序必须有定义：颜色与几何操作是否交换会影响结果。建议保存有序操作序列；预设只复用调色操作，默认不复制裁剪坐标。

## 八、实施安排与范围控制

建议顺序：编辑文档与历史 → 裁剪/拉直 → 安全导出/草稿 → 调色/预设 → 标注与局部工具 → 图层/RAW/AI。

单人、熟悉现有代码且持续投入的粗估：

| 阶段 | 粗略工作量 |
| --- | --- |
| P0 编辑基础 | 2–3 周 |
| P1 调色与预设 | 2–3 周 |
| 标注、马赛克与蒙版 | 2–4 周 |
| 图层、RAW、AI | 需要独立原型后重新估算 |

以上为规划估算，不是工期承诺；取决于图像质量标准、性能与验证结果。建议第一版明确为：电子相册 + 无损裁剪调色 + 撤销重做 + 安全导出。

## 九、验证重点

- 图像：横竖图、透明 PNG、EXIF 方向照片、不同色彩配置、大图。
- 坐标：适应窗口、1:1、缩放平移、高 DPI、旋转与裁剪组合。
- 生命周期：快速切换图片、后台预览取消、编辑中退出、草稿损坏。
- 文件安全：同路径导出、已有文件、无权限、磁盘失败；失败时原图和旧输出保持完整。
- 历史：滑块拖动、笔画、裁剪、多次撤销重做、恢复草稿后再次编辑。
- 回归：相册关闭重开、文件夹选择、照片墙、轮播音乐及 PDF。
