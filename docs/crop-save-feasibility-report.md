## 结论

可以实现。建议裁剪确认后提供“继续编辑”“另存为素材”“覆盖当前原文件”三个操作，默认继续编辑；保存选择中推荐另存为素材，覆盖必须明确选择并确认。裁剪预览期间不写磁盘，取消裁剪不保存。

这项功能适合为后续多图拼合准备矩形局部素材。不过保存矩形裁剪不会自动去除人物背景，也不会生成蒙版或实现图层合成。相关能力仍属于总计划 B/C 阶段。

## 当前项目已经具备的基础

- `PhotoEditDocument` 保留源图与编辑状态，裁剪存为源图矩形，`Render()` 可以生成当前完整尺寸结果。
- `PicShow::SlotCrop()` 确认裁剪后生成一条历史记录，目前不写文件。
- `ImageExportService` 已支持完整尺寸导出、编码选项和 QSaveFile 写入，普通导出目前明确拒绝源图路径。
- `PhotoWallModel` 的缩略图缓存按文件路径索引；树与照片墙通过照片集合变化通知联动。只修改磁盘文件不保证缓存和树列表自动刷新。
- `PhotoEditDocument::load()` 会重置编辑状态及基准，因此覆盖后重新加载不能继续直接套用旧裁剪参数。

## 建议交互与保存语义

### 裁剪确认之后

保留现有“应用裁剪”行为，进入结果预览，然后允许选择：

1. **继续编辑**：不保存文件，保持现有撤销重做。
2. **另存为素材**：选择位置和格式，默认 PNG 和名称如 `原名_crop_001.png`，避免默认重复覆盖同一个素材。
3. **覆盖当前原文件**：明确展示目标路径、输出尺寸、格式和备份位置，用户确认后执行。

推荐让“应用裁剪”与“保存裁剪结果”在同一窗口中易于找到，而不强迫每次裁剪后立刻保存。取消保存窗口只取消保存，已确认的裁剪仍保留，可继续编辑或撤销。

### 保存哪些效果

第一版建议保存“当前所见结果”：裁剪、旋转、镜像、调色和滤镜全部包含，输出完整尺寸像素。窗口应说明这一点，避免用户误以为仅写入裁剪几何。

如果需要“只裁剪原始像素、不包含调色”，应作为后续独立选项，明确旋转与镜像的处理方式，不能静默改变现有预览与输出的对应关系。

### 另存为素材

- 保留原文件和当前编辑源，避免连续截取多个区域时逐渐失去整张原图。
- PNG 作为默认素材格式；它支持透明像素且无损编码，但不会自动把矩形背景变透明。
- JPEG 可选，提示透明背景处理及有损重编码；继续提供质量选择。
- 保存到当前相册外也可成功；“加入当前相册素材列表”应是单独明确的选项。
- 自动加入相册必须走树节点、路径去重、照片集合和缩略图更新流程，不能只把文件写到相册目录。

### 覆盖当前原文件

- 通过独立保存意图授权，普通“导出副本”继续保护源文件；不能全局取消现有保护。
- 覆盖只支持能正确编码回去的格式，不能把 PNG 内容写入 `.jpg` 文件。源格式不支持或格式与扩展名不匹配时，第一版建议提示改用另存。
- JPEG 覆盖会再次有损编码；需要保留完整画质时优先另存 PNG。
- 覆盖前默认创建独立且不重名的原文件备份；备份失败则停止覆盖。备份应避免被普通照片扫描重复当成素材。
- 如磁盘源文件自加载后已被其他程序修改，应停止直接覆盖并提示重新选择，避免覆盖外部修改。
- 写入新结果时仍使用 QSaveFile，关闭直接写入回退；失败保留磁盘旧文件、当前编辑与历史。

## 覆盖成功后的状态策略

必须避免在已裁剪的新文件上重复应用旧裁剪、旋转和调色。

建议第一版采用明确的“新基准”策略：确认提示中说明覆盖成功后以保存结果作为新原图，并清空当前编辑历史；需要恢复覆盖前的照片时使用备份。

成功提交后，基于实际保存结果更新源图、默认 EditState、修改基准、信息面板、直方图及照片墙缩略图。JPEG 应以实际重新解码的输出作为新基准，不能把未压缩内存图直接视为磁盘文件的精确内容。若提交成功但重新读取失败，必须区分“文件已保存”与“界面未能重新加载”，保留备份及当前内存内容，不误报成完全没有写入。

如果希望覆盖后仍能 Ctrl+Z 恢复旧原图，就需要历史命令同时管理源图版本，而不是只记录 EditState；这会扩大当前历史架构，本报告不建议第一版同时加入。当前“恢复全部原图”在新基准策略下恢复的是刚保存的新原图，必须在覆盖确认中说明。

## 需要改进的现有代码

| 模块 | 当前行为与限制 | 建议改动 |
| --- | --- | --- |
| `picshow.cpp/.h` | `SlotCrop()` 仅生成编辑历史，`SlotSaveProcessedImage()` 提供普通导出 | 增加裁剪结果保存入口，协调继续编辑、另存素材、覆盖原图；共用保存流程，避免复制一套导出逻辑 |
| `imageexportservice.cpp/.h` | 普通导出统一拒绝所有源图路径 | 增加独立覆盖操作或明确的保存意图，校验目标确为当前源文件，处理备份、格式验证和安全提交；普通导出继续拒绝源路径，不能简单删除保护判断 |
| `photoeditdocument.cpp/.h` | `load()` 更新源图并重置参数和基准，失败时 `clear()`；文档尚无独立的成功保存状态 | 增加成功覆盖后的源图与基准切换，先验证新图再更新文档；另存保持当前源图、参数与历史，并为 A5 区分内容修改和成功保存状态 |
| `picshow.cpp` 的 `PhotoEditCommand`、`SlotSelectItem()` | 历史仅保存 EditState，切图先清空历史再读文件；读取失败会清空展示 | 覆盖后不直接调用切图槽处理重载；先读入实际输出，验证成功后统一切换文档并清空旧历史；失败保留当前内存图和备份，准确报告文件是否已保存 |
| `photowallmodel.cpp/.h`、`thumbnailloader.cpp/.h` | 缩略图按路径缓存，异步请求通过 generation 丢弃旧批次，当前主要由整体重置触发 | 覆盖后失效缓存并使旧请求作废，不能只删缓存；第一版可复用 Reset 与 SetPhotos，定点刷新需配套请求版本控制 |
| `protreewidget.cpp/.h`、`mainwindow.cpp` | 照片墙列表来自树节点，通过 SigPhotoSetChanged 刷新；写入磁盘不会自动登记素材 | 增加保存成功通知及素材登记入口，处理相册归属、目录节点、路径去重和既有照片导航关系，再通知照片墙更新 |
| `tests/albumfeaturetests.cpp` | 已验证安全导出与源文件保护，尚无裁剪覆盖保存测试 | 保留普通导出保护回归，新增连续另存、覆盖备份、新基准切换、重载失败和异步缩略图刷新检查 |

当前 `SlotSelectItem()` 会先清空撤销栈，再调用文档 `load()`；若读取失败，文档和展示会被清空。这是切图的现有行为，不能直接当成覆盖后的保存收尾流程使用。覆盖成功后的处理应分开表示“磁盘提交成功”和“界面基准更新成功”，避免重载失败时丢掉尚可保留的内存数据。

缩略图更新也必须覆盖正在运行的旧读取任务。当前 ThumbnailLoader 已有 generation 机制可复用：先重置旧批次，再清缓存并请求新图；后续如优化成只刷新单张，需要给单路径请求增加同等的版本验证。

## 适合程度、计划调整与建议顺序

建议纳入项目，作为 A4 的补充需求与 A5 联动完成。另存素材直接服务后续 B 阶段的多图拼合；覆盖原图满足普通保存需求，但涉及源图替换、备份和历史基准，改动范围明显大于另存。现有文档、裁剪和安全编码服务均可复用，不需要重写整个编辑器或提前引入多图文档。

### 第一步：另存素材与相册登记

1. 在裁剪结果处增加另存素材入口，复用安全导出服务，默认 PNG 和不重名编号。
2. 保存当前完整尺寸可见效果；另存成功不切换编辑源，支持从同一原图连续提取不同区域。
3. 提供可选“加入当前相册”，完成树节点登记、去重和照片墙刷新；未选择加入时只保存文件。
4. 验证取消不丢裁剪、原图字节不变、两份局部素材均能独立打开。

### 第二步：覆盖原图与新基准

1. 增加独立覆盖保存操作与确认，校验源路径、格式以及外部修改。
2. 建立备份后安全提交；备份或提交失败保留旧源图、当前编辑与历史。
3. 读取实际保存结果，成功后切换源图、默认参数和修改基准，清空旧历史并刷新缩略图；重载失败走独立保留路径。
4. 在确认提示中说明：覆盖成功后“恢复全部原图”恢复到新保存的版本，覆盖前照片从备份恢复。

### 与总计划和离开提醒衔接

总计划已将 A4 原有的“禁止覆盖源图”验收要求调整为“普通导出与素材另存禁止覆盖；明确选择覆盖保存时，经过确认、备份和安全提交允许替换”，并区分三种保存意图。该调整属于规划，当前代码仍禁止覆盖源图。

成功保存状态与 A5 统一处理：取消、失败不得标记为已保存；另存副本不改变“与原图不同”的内容判断；覆盖建立新基准后须使用实际输出判断当前状态。上述建议已合入总计划的状态表、执行顺序、模块职责和 T13–T18 验收；A4a 已实现并通过常规与 200% 离屏回归；A4b 仍为待实现。

## 验收项目

- 裁剪后另存的尺寸、方向、像素和透明度正确，源文件字节不变；连续提取两个不同区域不丢失原图。
- 保存窗口取消不产生文件，裁剪编辑仍可撤销；同名素材覆盖有明确确认。
- 普通导出仍拒绝源路径，只有明确选择覆盖的流程能够写回。
- 覆盖前备份与旧文件一致；备份失败、文件占用、磁盘空间不足或提交失败不破坏旧源文件。
- 源文件被外部修改时不会直接覆盖；不支持的编码与扩展名不匹配会阻止覆盖。
- 覆盖后重新打开与磁盘结果一致，裁剪和调色不重复应用；历史、修改状态和缩略图符合新基准策略。
- JPEG 保存质量、白色透明背景以及重新解码后的显示符合预期，不承诺完整保留全部 EXIF/ICC 等元数据；如需要保留，须专项实现及验证。
- 另存素材加入相册后能被照片墙和后续素材选择入口发现，重复登记不生成重复节点。
