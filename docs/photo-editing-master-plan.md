# 电子相册图片编辑与多图合成总计划书

版本：2.2

整合日期：2026 年 10 月 27 日
项目技术：C++17、Qt 6.8.3、CMake  
文档性质：整合当前基础修图与后续图片合成的开发、验收和交付安排；规划功能不等于已经实现。

## 一、总目标与文档约定

建立两条相互衔接的使用流程：

- 单图修图：打开照片 → 裁剪、旋转与调色 → 原图对比 → 撤销重做 → 安全导出副本。
- 多图合成：新建画布 → 添加图片图层 → 排列与变换 → 选区和蒙版（后续阶段）→ 保存可编辑工程 → 导出成品。

本文件整合 [基础修图计划](basic-photo-editing-plan.md)、[多图合成计划](image-compositing-plan.md)及[裁剪保存可行性报告](crop-save-feasibility-report.md)，作为开发顺序、范围、保存规则和验收的统一入口。专项文档保留详细要求与研究依据；如进度和优先级描述存在差异，以本文件为准。photo-editor-roadmap.md 保留为更长期的能力参考。

“裁剪”改变矩形画面范围；“拼合”把多张照片放入一个画布；“抠图”借助选区和蒙版提取局部。它们不是同一个功能，不以完成矩形裁剪代替完成图层合成。

## 三、下一步执行顺序

1. 对现有裁剪进行实机验收：八个控制点、缩放平移、旋转镜像、重复裁剪、确认取消及撤销重做。
2. 原图对比和“恢复全部原图”已实现。按住对比单独适应窗口，释放恢复结果和原有视图，不改编辑或历史；切图、清空、加载失败、隐藏和失活时结束对比。恢复全部原图作为一条历史记录清除所有编辑；现有“还原参数”继续只清除调色与滤镜。
3. 共享 ImageExportService 已实现：从文档全尺寸渲染，PNG/JPEG/BMP 通过 QImageWriter 编码到 QSaveFile，关闭直接写入回退；支持透明背景、JPEG 质量、源路径保护和失败保护。界面默认 PNG 副本，JPEG 使用明确的白色背景和可选质量。自动回归覆盖全尺寸编辑像素、透明度、成功替换、无效目标及源文件保护；补充真实保存窗口的取消、格式选择和覆盖确认验收。
4. **已实现 A4a：裁剪结果另存为素材**。默认 PNG 和不重名编号，保留当前源图与历史，支持连续提取局部；提供可选加入相册、路径去重和照片墙刷新。
5. **下一模块 A4a-D：素材删除与回收站**。在照片墙和树节点提供删除入口，确认后将相册内实际素材文件移入回收站；成功才移除节点和缓存并修复导航，关闭重开不再出现。外部导入素材只删除相册副本，外部文件保留；失败保留列表，删除当前编辑图片前处理未保存编辑。
6. **随后 A4b：覆盖原图**。独立保存入口，确认后备份并安全提交；检查外部修改，成功后读取实际结果、建立新基准并清空旧历史；重载失败保留内存内容，刷新缩略图时丢弃旧异步结果。
7. 接入 A5 保存状态与离开提醒，区分副本导出、素材另存和源图覆盖；完成 A1–A5（含 A4a、素材删除及 A4b）验收，形成可交付 V1。
8. 从最小 CompositionDocument 和两图渲染原型开始 B 阶段，使用原始照片或另存素材，依次接入画布、图层交互、历史和工程保存，形成 V2。
9. V2 稳定后加入选区和蒙版，完成手动抠图换背景流程，再评估融合增强。

不在单图安全导出尚未完成时同时重写整个合成工作区；每一步完成后再扩大范围。用户明确指定更换优先级时，可开发独立合成原型，但交付状态必须单独记录。

## 四、共享规则与两类文档的边界

| 项目 | 单图修图 | 多图合成 |
| --- | --- | --- |
| 文档 | PhotoEditDocument，源图和编辑状态唯一来源 | CompositionDocument，画布、资源及图层唯一来源 |
| 页面 | PicShow 协调单图操作 | 独立合成工作区协调多图操作 |
| 历史 | 单图 EditState 前后状态 | 稳定图层 ID 与增删、属性和排序变化 |
| 重置 | “还原参数”只重置调色；“恢复全部原图”清除所有编辑 | 按对象和操作明确范围，不能误删其他图层 |
| 内容修改 | 与加载或明确处理后的编辑基准比较 | 与最近成功保存的工程内容基准比较 |
| 导出图片 | 成品副本，不提供重新恢复参数的能力 | 合并成品，不代替图层工程保存 |
| 保存工程 | 草稿为后续增强，V1 不承诺 | V2 必须，包含资源与图层，能够重开继续编辑 |
| 可复用能力 | ImageProcessor、QImage 渲染、ImageExportService、验证工具 | 共用算法和文件安全机制，不共用不适配的单图命令 |

单图需区分“内容与原图不同”和“当前编辑是否已通过合格导出处理”。保留加载基准的内容比较，同时为成功的全尺寸导出记录对应 EditState。仅当输出成功且内容状态相同，才允许离开提醒将其视为已处理；导出后继续编辑或撤销到其他状态应重新判断。导出失败、取消、分享缩略图不得清除提醒。切图后重新建立基准。安全导出服务已经接入；成功导出状态记录及上述提醒策略在 A5 实现，当前导出不会清除内容修改标记。

规划的素材另存继续使用原始编辑源，成功后不清空参数或历史；覆盖保存成功且新结果验证通过后，以实际磁盘结果建立新源图和默认 EditState，清空旧历史。覆盖前版本从备份恢复，Ctrl+Z 不承担跨源图版本恢复。“恢复全部原图”及对比入口在新基准下对应新保存的源图，覆盖确认须说明这一变化。A4a 已实现并通过相关自动回归；A4b 尚未实现。

合成工程成功保存后才更新工程基准；导出 PNG/JPEG 不清除“工程未保存”。选择图层、显示缩放和平移不属于内容修改；图层位置、名称、显隐、锁定、排序、蒙版和画布设置属于需保存内容。

单图沿用“原图裁剪 → 镜像 → 90 度旋转 → 可选降采样预览 → 调色”的当前顺序。多图合成采用后文规定的源图/图层/画布坐标与处理顺序。两者不会因共用算法而自动等价；后续将单图编辑结果加入合成时，应明确选择导入源图还是完整尺寸处理结果，不静默更换顺序。

所有阶段保持 8 位图像处理定位，不宣称 RAW/HDR 或完整专业色彩管理；明确 EXIF 方向、透明度、输出颜色策略和元数据保留限制。

V1 默认导出副本或另存素材，两者均阻止输出路径指向原图；只有明确选择“覆盖原图”并通过确认、备份和安全提交流程才允许替换源文件。对其他已有输出文件也须明确确认。当前代码仍禁止覆盖源图，新增覆盖入口属于待实现范围。

V1 不包含视频剪辑、复杂抠图、人像精修、图层合成、RAW、HDR、完整印刷色彩管理和 AI 生成式处理。基础多图拼合和手动蒙版已在本总计划 B/C 阶段安排，但不计入 V1 验收。

### A 模块职责

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| PhotoEditDocument | 保存原图、参数、几何编辑状态和修改状态 | 不直接操作界面控件 |
| PicShow | 展示图片，接收控件操作，协调编辑流程 | 不再重复保存调色参数 |
| ImageProcessor | 根据输入图像和参数执行计算 | 不读取滑块或弹出窗口 |
| QUndoStack 与编辑命令 | 保存前后状态，执行撤销重做 | 不为每次滑动复制整张图片 |
| CropTool | 裁剪框交互、比例约束、坐标转换、确认取消 | 预览期间不永久改写原图 |
| ImageExportService | 全尺寸渲染、编码、安全写入；扩展保存意图、备份及覆盖校验 | 普通导出保护源图，覆盖必须走独立验证流程 |
| PhotoWallModel / ThumbnailLoader | 素材展示、缩略图加载与缓存失效 | 覆盖后的旧异步结果不得回填缓存 |
| ProTreeWidget / MainWindow | 素材归属、路径去重、树节点登记和跨模块通知 | 写文件成功不等于已登记相册 |

编辑数据的唯一来源是 PhotoEditDocument。PicShow 的滑块和数值标签只是状态的显示与输入入口。

#### 参数读写约定

文档通过 parameters() 返回参数副本，通过 setParameters() 接收整套参数。界面先读取副本，修改对应数值，再统一交回文档。文档负责限制亮度、对比度和饱和度的有效范围。

PicShow 的重复状态成员已经删除。通过整套参数和 EditState 管理文档，不要求恢复已清理的亮度便捷接口。

#### 渲染顺序约定

裁剪区域已使用原图整数像素坐标保存，确认时将当前显示方向的选区反向映射到原图。统一顺序见第四节；预览与全尺寸图像共用文档渲染定义。

Render(previewMaxSize) 保留拖动时的降采样优化；全尺寸导出不传预览上限。滤镜与几何操作顺序不能随重构改变。

### A 开发步骤与完成条件

#### 阶段一 统一编辑状态

1. 为 PhotoEditDocument 添加 parameters() 和 setParameters()。
2. 让亮度、对比度、饱和度及滤镜统一写入文档。
3. 让渲染读取文档参数，保留现有输出与交互行为。
4. 同步改造加载、重置、清空、加载失败和图片切换逻辑。
5. 删除旧参数，检查所有引用和初始化代码。

完成条件：四类参数调节正常；控件与文档一致；切换照片不继承上一张效果；加载失败不会残留旧图；清空后不再渲染旧文档。

#### 阶段二 撤销与重做

使用 QUndoStack 和 QUndoCommand 记录编辑前后状态。一次滑块拖动合并为一次历史操作，键盘或鼠标步进也应形成合理操作单位。恢复控件时阻止信号递归生成新命令。

旋转、镜像与恢复默认状态一并纳入历史。每张照片使用独立历史，或切换时明确清空当前历史，避免撤销到另一张照片。

完成条件：连续调整后可以逐步撤销重做；分支编辑正确清除失效的重做记录；界面、文档和预览始终一致。修改状态应反映当前是否存在未处理的编辑，不能只用历史索引判断导出状态。

#### 阶段三 裁剪

支持移动裁剪框、八个控制点、比例锁定和结果尺寸显示。进入工具时建立临时状态；确认后生成历史命令；取消时恢复进入工具前的状态。

建立屏幕坐标、画布坐标与图像坐标的转换。处理缩放、平移、高 DPI、旋转镜像及图像边界，裁剪宽高不得为零。固定比例在边界附近也必须保持有效。

完成条件：不同显示缩放下选取同一区域，导出像素区域一致；旋转镜像后裁剪方向正确；裁剪可撤销；取消不产生实际编辑。

#### 阶段四 原图对比与导出

原图对比只切换显示，不修改文档和历史；明确原图与编辑后图像的显示适配方式。

导出从原始图像和当前编辑状态重新生成全尺寸 QImage。使用 QImageWriter 编码到 QSaveFile，成功后提交，失败则保留原目标文件。JPEG 遇到透明像素时使用明确背景色。根据运行时支持情况启用编码格式。

完成条件：输出方向、尺寸、透明度和效果正确；拖动预览不会导致低分辨率导出；失败或取消不损坏原图和已有输出。

#### 阶段四补充：A4a 另存素材（已实现）与 A4b 覆盖保存（待实现）

裁剪确认只生成编辑记录，不直接写盘。在结果处提供继续编辑、另存素材和覆盖原图；取消保存只取消写入，保留已确认的裁剪。保存包含当前完整尺寸的裁剪、旋转、镜像、调色和滤镜，矩形素材不等同于抠图或图层合成。

A4a 默认命名为 `原名_crop_001.png` 并递增避让已有文件。另存后不切换源图，用户可撤销本次裁剪再截取其他区域。加入当前相册为独立选项，处理目录归属、树节点、路径去重及导航关系；加入失败须与文件保存成功区分，不将已保存文件误报为未写入。

A4a 实现记录（2026-10-27）：裁剪按钮下方提供“另存为素材…”，无有效裁剪时禁用；MaterialSaveDialog 提供编号 PNG 路径、可选入册和 JPEG 质量。保存使用文档快照与现有安全导出服务。相册内素材直接登记，外部素材复制到相册“素材”目录后登记，相同内容副本复用、不同内容同名避让；重建导航链并通过照片集合通知刷新照片墙，不自动切换当前编辑源。未勾选入册时只保存文件；若保存位置在相册目录内，重开扫描仍会发现该文件。关闭或忙碌的相册拒绝登记，并单独提示文件已保存。已验证连续裁剪、颜色和透明像素、取消与写入失败、编号、源文件和历史保护、相册上下文、路径去重、外部复制、导航、照片墙及重开；常规与 200% 离屏回归通过，保存窗口截图已检查。原生文件选择与真实鼠标操作仍待手工验收。

A4b 先验证实际源格式、扩展名、编码能力和外部修改，再建立不重名备份；备份失败停止覆盖，继续关闭 QSaveFile 直接写入回退。提交成功后读取实际保存结果，JPEG 使用重新解码后的像素；验证通过再切换文档、基准和历史。提交失败保留旧文件及编辑；提交成功但重载失败保留内存内容与备份，分别报告保存和重载状态。

覆盖后不能直接调用现有 `SlotSelectItem()` 收尾，因为它先清空历史，加载失败还会清空文档。需要先验证新图，再更新源图、参数、修改基准、信息面板和直方图。缩略图更新必须使旧异步请求失效；第一版可复用 ThumbnailLoader::Reset() 和 PhotoWallModel::SetPhotos()，后续再做逐路径版本控制。

#### 阶段四补充：A4a-D 素材删除与回收站（待实现，优先于 A4b）

删除是将相册内实际素材文件移入操作系统回收站。不能只移除树节点、隐藏条目或清缓存，否则文件仍在相册目录，重开扫描就会重新出现。删除成功后，该素材在原路径不再存在，关闭并重新打开相册不得再次扫描出来；用户主动从回收站恢复文件后，重新扫描可再次发现。

照片墙与树节点提供删除入口，确认中明确显示目标文件路径。对于从相册外复制加入的素材，仅移动相册内副本，不删除外部保存的文件。对于直接保存在相册内的素材，移动该实际文件；路径归属与别名必须校验，避免操作指向相册外文件。

执行顺序为：确认目标 → 若目标正在编辑，处理未保存编辑并允许取消 → 尝试移入回收站 → 成功后移除相关树节点和照片墙条目、收藏记录及缩略图缓存，作废旧异步缩略图请求并修复前后导航。删除当前展示图片时，成功后安全切换到有效图片或清空展示，避免悬空节点引用。取消或失败保留条目、文件及编辑状态，并提示原因；回收站不可用时不得自动改为永久删除。批量删除如实现，按每个文件实际结果更新，失败文件继续保留。

删除操作不加入目前只记录 EditState 的编辑撤销栈；文件恢复通过系统回收站完成。无需用“隐藏名单”替代实际删除。实现可复用现有回收站能力，但单张素材删除、路径验证和界面同步须单独接入验证，不能将现有相似照片清理视为已经实现此功能。

#### 阶段五 完整流程与离开提醒

编辑后切换图片或关闭页面时提供导出副本、放弃修改、取消离开。导出失败或用户取消保存窗口时继续停留，不丢弃编辑。

第一版未保存草稿时应说明：导出结果是成品图片，不能代替可恢复参数的编辑工程。若后续允许导出尺寸、质量变化，应区分原尺寸成品导出与分享缩略图，避免误清除修改提示。

完成条件：用户可以完整完成打开、编辑、对比、撤销重做、导出和离开流程，且已有相册功能正常。

### A 图像与文件处理要求

原始图像不反复覆盖，避免累积压缩和失真。第一版沿用现有 8 位图像处理能力，不宣称已支持 16 位、RAW 或专业印刷色彩。

加载时明确处理 EXIF 方向；预览和导出保持一致，避免重复旋转。元数据保留能力必须单独验证，不默认承诺完整保存 EXIF。优先建立明确的 sRGB 输出策略，后续再扩展色彩管理。

预览可以缩小图像，最终导出必须重新计算。后续引入后台预览时，后台只处理 QImage 与数据，GUI 线程负责 QWidget 和 QPixmap；过期任务结果不能覆盖新参数或另一张照片。

## 六、B 阶段：可编辑的多图拼合

### 功能范围

1. 新建画布：自定义宽高、背景颜色或透明背景；像素尺寸与窗口显示尺寸分离。
2. 添加图片：支持一次选择多张图片，每张作为独立图片图层；首次导入自动缩放到画布可见区域，不改变源图像素。
3. 图层列表：选择、重命名、显示/隐藏、锁定、复制、删除以及上移/下移；明确列表上方表示画面前方。
4. 图层变换：移动、保持比例缩放、任意角度旋转；提供数值输入，支持确认和取消。第一版不允许无意翻转或缩放到零。
5. 图层透明度：0–100%；第一阶段仅提供普通透明叠加，不预先承诺所有专业混合模式。
6. 撤销重做：增加、删除、复制、排序、显隐、锁定、重命名、变换、透明度及背景设置；一次连续拖动记为一步。
7. 保存工程：保存后能够重新打开并继续移动图层；导出成品图片不代替保存工程。
8. 导出副本：全画布 PNG、JPEG；透明 PNG 保留透明，JPEG 按用户选择的背景色合成，提供质量设置。
9. 离开提醒：保存工程、放弃或取消离开；保存失败或取消保存时不得丢失编辑。

### 典型操作流程

新建 1920×1080 画布 → 添加背景照片和前景照片 → 选择图层 → 调整位置/大小/角度 → 调整前后顺序和透明度 → 保存工程 → 导出图片。

### 第一阶段不包含

自动抠图、复杂蒙版、曲线、图层组、文字排版、透视变换、RAW/HDR、PSD 导入导出、AI 生成、云端图片上传。这些功能按后续阶段分别评估。

## 七、C 阶段：选区与非破坏性蒙版

1. 先实现矩形、椭圆选区，再增加多边形套索；支持添加、减去、反选、清除及边缘羽化。
2. 将选区转换为当前图片图层的蒙版，允许保留选中部分或隐藏选中部分。
3. 蒙版使用图层源图坐标；黑色隐藏、白色显示、灰色部分透明，保留原始图像。
4. 增加画笔擦除/恢复蒙版，提供大小、硬度和强度；一次笔画形成一步历史。
5. 支持临时关闭、删除、反相蒙版，以及单独查看蒙版；蒙版随图片一起移动、缩放和旋转。
6. 工程保存包含蒙版，重新打开后继续修改；导出时合成到最终画布。

验收示例：从人物照片中手动选出主体 → 添加蒙版 → 放到另一张背景照片上 → 调整大小与位置 → 修改边缘 → 保存工程并重开 → 导出成品。

自动人物分割或背景移除属于后续独立研究项，不能把手动蒙版能力称为自动抠图。

## 八、D/E 阶段：融合增强与长期研究

- 增加正片叠底、滤色等少量常用混合模式，逐一验证透明度、色彩和预览/导出一致性。
- 每个图片图层独立调色，初期复用亮度、对比度、饱和度；明确只处理当前图层，不影响其他图层。
- 增加对齐、吸附、等间距排列和常用拼图布局；布局应用也应可撤销。
- 视需要增加文字、水印、投影与图层组；每类功能单独设计数据和历史命令。
- 最后再评估自动抠图、背景替换等模型功能的质量、部署体积、授权和硬件需求。

## 十、合成坐标与渲染约定

统一定义三种坐标：图层源图像素坐标、合成画布像素坐标、窗口逻辑坐标。显示缩放和平移仅改变最后一种映射，不能改变图层的画布位置或导出尺寸。

图层以源图中心为变换锚点，保存画布中心位置、缩放和旋转角度。渲染顺序为：源图解码并处理方向 → 图层裁剪（如支持）→ 图层调色 → 蒙版与源透明度结合 → 图层变换 → 图层透明度及混合 → 按顺序叠加到画布。蒙版坐标绑定源图，裁剪只限制可见区域；扩展功能时必须维持这一约定或升级工程格式。

命中测试按图层前后顺序反向查找，并使用逆变换映射到图层局部坐标。第一阶段可先按变换后的图层矩形命中；透明像素穿透选择作为后续增强。锁定图层不可拖动修改，但允许在列表中选择。

预览可降低显示分辨率，但位置、蒙版和变换以原始坐标保存。导出从源资源和文档状态重新渲染，不保存窗口截图；后台任务仅处理 QImage 和数据，过期结果不得覆盖新文档。

## 十一、工程保存与文件安全

第一阶段工程建议采用单文件容器，内含版本化 JSON 清单和资源区。可用 QSaveFile 配合 QDataStream 写入；每个资源使用明确长度与 ID，读取时检查版本、尺寸、数量和资源长度。版本未知或文件损坏时，报告失败，不覆盖当前已打开文档。

为了便于交给老师测试，工程内嵌图片资源，不依赖开发机器的绝对路径。保存原始编码资源和方向信息，或采用明确的无损资源表示，不能每次保存都反复 JPEG 压缩。重新打开工程不恢复完整撤销历史，建立新的已保存基准即可。

修改状态比较当前文档内容与最近成功保存的工程基准，包括画布、图层属性、排序和蒙版；当前选择、窗口缩放和平移不算内容修改。保存失败不更新基准；撤销回已保存内容应恢复未修改。导出 PNG/JPEG 只生成成品，第一阶段不清除“工程尚未保存”的提示。

导出拒绝覆盖任何输入源图片及当前工程文件。使用 QImageWriter 写入 QSaveFile，成功才提交；禁止为临时写入失败开启直接覆盖回退。覆盖已有输出先明确确认；导出失败必须保留旧目标文件。

| 3 | 移动、缩放、旋转、显隐与透明度 | 不同显示缩放下位置一致；连续拖动只生成一步历史 |

| 5 | 导出及完整交互验收 | 全尺寸成品与画布一致，失败不损坏源图或旧输出 |
| 6 | 选区、蒙版及画笔 | 人物局部可放入背景，边缘与历史恢复正确 |
| 7 | 混合模式、图层调色等增强 | 每项单独通过像素和交互验证 |

不以“已创建类或已增加按钮”作为完成功能的依据。每步都应提交可运行的最小结果和相应验证记录。

## 十三、合成验收清单（C01–C14）

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| C01 | 两张不透明图片部分重叠，交换层序 | 重叠处像素来自正确图层 |
| C02 | 透明 PNG 与不同透明度叠加 | 透明边缘正确，无意外黑边或底色 |
| C03 | 缩放、平移、高 DPI 下移动同一对象 | 导出的画布位置与尺寸一致 |
| C04 | 任意角度旋转、缩放及撤销重做 | 位置、角度、大小和预览恢复准确 |
| C05 | 删除、复制、排序及分支编辑 | 资源可恢复；旧重做分支被清除 |
| C06 | 取消变换或导入损坏图片 | 不留下半完成图层，不改变原有内容 |
| C07 | 保存工程、移动原始素材、重开工程 | 图片、层序、变换和透明度完整恢复 |
| C08 | 保存失败、损坏或未知版本工程 | 当前工程及已有目标文件保持完整 |
| C09 | PNG/JPEG 全尺寸导出与透明背景 | 输出尺寸正确，JPEG 背景色明确 |
| C10 | 输出指向素材、工程或无权限路径 | 阻止危险覆盖，失败不会损坏已有文件 |
| C11 | 修改后退出及导出但未保存工程 | 提供保存、放弃、取消；导出不冒充工程保存 |
| C12 | 蒙版笔画、移动旋转、保存重开及撤销 | 第二阶段验收：蒙版绑定正确，边缘和历史一致 |
| C13 | 大图、多图层及快速切换工程 | 内存与耗时可观察；关闭后无悬空任务或旧结果覆盖 |
| C14 | 原有相册、单图修图、音乐和 PDF | 合成模块不破坏原有流程 |

图层数量及画布尺寸上限应通过目标电脑实测确定，并在界面明确提示；不能在未经测量时承诺无限图层或任意尺寸。以目标画布和最大预期素材做压力原型，再确定可交付范围。


## 十四、交付与验证记录

每个阶段交付可运行程序、源代码、使用说明和验收记录；发布前重新构建实际运行目录，并在目标 Windows 电脑验证部署依赖。新工程格式应记录版本及兼容范围。大图、图层数量和画布上限通过实测确定，不承诺无限资源。

测试记录应注明静态检查、像素自动测试、离屏事件测试和实机交互的区别。已有通过记录只覆盖当时的实现，代码变更后按受影响范围重新验证。安全导出已有代码与自动测试记录；工程保存和蒙版仍属规划，不能标成已完成。

基础版按 T01–T22 验收，包含裁剪保存与删除扩展；多图拼合按 C01–C11、C13、C14 验收；蒙版阶段增加 C12。跨阶段都应验证原有相册打开/导入/关闭、音乐和 PDF 回归。
